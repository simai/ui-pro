# sf-mail-library

Библиотека блоков письма SIMAI — редактора писем: блоки, которые можно добавить
в письмо, по группам назначения, с чипами категорий и поиском по названию и
описанию. Перенесена из `simai/ui-mail` (`package/src/smart/mail-library`,
0.2.0, коммит 330720b) по решению владельца D31 от 2026-10-29: продуктовые
репозитории не делают своих наборов компонентов, общие компоненты живут в
ui-pro. Имя осталось прежним.

Строка добавляет свой блок: элемент сообщает `sf-mail-library-add {type}`, а
куда вставить блок, решает хост. Сам элемент письмо не меняет.

## Данные

Блоки — это данные, а не зависимость: хост передаёт их свойствами (или JSON-
островом, который печатает сервер) на языке человека.

```js
library.groups = [{id: 'basics', title: 'Основа'}, {id: 'commerce', title: 'Товары'}];
library.items = [
  {type: 'heading', title: 'Заголовок', purpose: 'Главная мысль письма', icon: 'title', group: 'basics'},
  {type: 'price', title: 'Цена', purpose: 'Цена и старая цена', icon: 'sell', group: 'commerce'},
];
library.addEventListener('sf-mail-library-add', (event) => addBlock(event.detail.type));
```

Строка, чьей группы нет в `groups`, не показывается. Группа, в которой после
поиска не осталось строк, не рисуется. Если не найдено ничего — показывается
`sf-empty-state` «Ничего не найдено».

## Категории

`category` — `all` или id одной группы. Чипы одной строкой над списком, лишние прокручиваются, («Все» и по одному
на группу; их нет, если группа одна) переключают его; выбранный чип —
`aria-pressed="true"`. Пока выбрана категория, раздел «Шапка и подвал» скрыт:
категория — про содержание. Id, которого нет среди групп, показывает все
группы, так что устаревший фильтр не оставит Библиотеку пустой.

## Шапка и подвал

```js
library.places = [
  {family: 'header', title: 'Шапка', current: 'header-logo', items: [
    {type: 'header-logo', title: 'Логотип', purpose: 'Логотип по центру', icon: 'image'},
    {type: 'header-band', title: 'Полоса', purpose: 'Цветная полоса с логотипом', icon: 'view_carousel'},
  ]},
];
library.addEventListener('sf-mail-library-replace', (event) => replaceVariant(event.detail.family, event.detail.type));
```

Вариант из `current` отмечен галочкой и `aria-pressed="true"` и повторно не
предлагается: нажатие на него ничего не сообщает, действие `replace` отвечает
`refused current`. Другой вариант сообщает
`sf-mail-library-replace {family, type}`, а заменяет хост — одним шагом,
который можно отменить, — и передаёт новый `current` обратно в `places`.

## Поиск

`query` — слова поиска; поле внутри элемента записывает его, пока человек
печатает. Блок находится по названию, по назначению и по своему типу.

## Действия

| Действие | Что делает | Ответ |
|:---|:---|:---|
| `search {query}` | ищет, как поле | `applied` |
| `filter {category}` | показывает одну группу или все, как чип | `applied` |
| `add {type}` | добавляет блок, как его строка | `applied`; `refused unknown`, если такого блока нет |
| `replace {family, type}` | выбирает вариант места, как его строка | `applied`; `refused current` для текущего варианта, `refused unknown` для неизвестного |

## Клавиатура и доступность

Сначала поле поиска, затем чипы, затем каждая строка — обычная кнопка в порядке
Tab; Enter или пробел добавляют блок или меняют вариант. Группа —
`role="group"` с названием, сам заголовок группы скрыт от чтения с экрана,
чтобы не звучать дважды. Имя кнопки — её же слова (название и назначение
блока), затем действие, поэтому голосовая команда с названием блока до неё
доходит. «+» — украшение, видно при наведении и фокусе.

## Что изменилось при переносе

- Событие `sf-mail-library-variant` теперь называется `sf-mail-library-replace`
  (у запроса — глагол, словарь 1.1.5 §5.1). Элемент не выпускался, поэтому
  старого имени-псевдонима нет.
- Метод `choose(family, type)` стал действием `replace {family, type}`; `add`,
  `search` и `filter` — действия, они принимают объект или параметры по порядку.
- Слова — в `lang/ru.json` и `lang/en.json`.
